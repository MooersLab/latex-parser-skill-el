* Introduction
#+INDEX: introduction
#+INDEX: transcript-parser skill

latex-parser-skill turns raw dictated or transcribed text in a LaTeX buffer into a structured LaTeX fragment.
The fragment has one =\subsubsection= per topic, =\index= keys below each heading, one sentence per line, expanded contractions, and a closing checklist of TODO items.
The rules come from the transcript-parser skill, and a copy of its instructions ships with the package.

The package is meant for text that did not pass through a dictation tool with its own clean-up step.
That text still holds contractions and dictation errors, so the package fixes the predictable ones before the model sees it.

An analogy from crystallography describes the four stages.
Stage 1 is like data reduction because it is deterministic and repeatable.
Stage 2 is like model building because it needs judgment.
Stage 3 is like validation because it checks the model against fixed rules.
Stage 4 is like a short round of rebuilding guided by the validation report.

#+ATTR_LATEX: :booktabs t
#+CAPTION: The four stages of the pipeline.
| Stage | Name         | Kind          | What it does                                                |
|-------+--------------+---------------+-------------------------------------------------------------|
|     1 | Replacements | Deterministic | Expands contractions and applies your dictation rule files  |
|     2 | Parse        | Model         | Sends the skill instructions and the text to the backend     |
|     3 | Verify       | Deterministic | Checks the reply against the rules of the skill              |
|     4 | Repair       | Model         | Sends the list of violations back for a corrective pass      |

* Installation
#+INDEX: installation
#+INDEX: MELPA

The package needs Emacs 28.1 or later.
Install it from MELPA with =M-x package-install RET latex-parser-skill RET=.

To install from the repository with Emacs 29 or later, use the =:vc= keyword of =use-package=.

#+begin_src emacs-lisp
(use-package latex-parser-skill
  :vc (:url "https://github.com/MooersLab/latex-parser-skill-el" :rev :newest))
#+end_src

A manual install needs only the repository on the =load-path=.

#+begin_src emacs-lisp
(add-to-list 'load-path "~/6112MooersLabGitHubLabRepos/latex-parser-skill-el")
(require 'latex-parser-skill)
#+end_src

See the chapter on key bindings for the suggested =C-c t= prefix.

* Backends
#+INDEX: backends

A backend sends the system prompt and one user message to a model and returns the reply.
Every backend is asynchronous, so Emacs stays responsive.
Choose the default with =latex-parser-skill-backend= and switch for the session with =C-c t m=.

#+ATTR_LATEX: :booktabs t
#+CAPTION: Built-in backends.
| Backend             | Transport                                 | Leaves the computer      |
|---------------------+-------------------------------------------+--------------------------|
| =claude-code=       | The =claude= program in print mode        | Yes                      |
| =anthropic-api=     | The Claude Messages API over HTTPS        | Yes                      |
| =openai-compatible= | A =/v1/chat/completions= server           | Only for a remote URL    |
| =gptel=             | Whatever model gptel is set up to use     | Yes, unless you say no   |

** Claude Code
#+INDEX: claude-code backend

This is the default backend.
It runs =claude -p= with the transcript on standard input.
The bundled prompt replaces the system prompt, and every tool is turned off with =--tools ""=, so the model only writes text.
Sessions are not saved, because the command passes =--no-session-persistence=.

#+begin_src emacs-lisp
(setq latex-parser-skill-claude-model "sonnet")   ; nil uses the program default
#+end_src

Set =latex-parser-skill-claude-prompt-source= to =skill= to rely on a transcript-parser skill installed in Claude Code instead of the bundled prompt.
Extra command-line arguments go in =latex-parser-skill-claude-extra-args=.

** Claude API
#+INDEX: anthropic-api backend
#+INDEX: auth-source

The key comes from auth-source under the host =api.anthropic.com=, or from the environment variable =ANTHROPIC_API_KEY=.
A line in =~/.authinfo.gpg= looks like this.

#+begin_example
machine api.anthropic.com password sk-ant-...
#+end_example

The model is =latex-parser-skill-anthropic-model=.

** Local models
#+INDEX: openai-compatible backend
#+INDEX: Ollama
#+INDEX: llama.cpp

Any server that speaks the chat completions protocol works, including Ollama, the llama.cpp server, LM Studio and vLLM.
The default URL is the Ollama server on this computer.

#+begin_src emacs-lisp
(setq latex-parser-skill-openai-url "http://localhost:11434/v1/chat/completions"
      latex-parser-skill-openai-model "your-model-tag")
#+end_src

A server that needs a key reads it from auth-source under the host of the URL.
Requests set the temperature to zero.
Replies from reasoning models often begin with a =<think>= block, which the package removes.

Local models have smaller context windows.
=latex-parser-skill-chunk-sizes= splits long input at blank lines for named backends, and its default limits =openai-compatible= to 12000 characters per request.
The trade-off is that a topic that spans two chunks may get two headings.
The merge step collects every TODO item into one block at the end.

** gptel
#+INDEX: gptel backend

The gptel backend reuses the model that gptel already knows about.
It uses =gptel-backend= and =gptel-model= unless =latex-parser-skill-gptel-backend= or =latex-parser-skill-gptel-model= say otherwise.
gptel is optional, and the package loads it only when this backend runs.
Set =latex-parser-skill-gptel-remote= to nil when gptel talks to a local server, so that no confirmation is asked.

** Writing a new backend
#+INDEX: custom backend

Register a function of four arguments.
It receives the system prompt, the user message, a success callback and an error callback, and it returns a handle.

#+begin_src emacs-lisp
(latex-parser-skill-register-backend
 'my-backend
 :request (lambda (system text callback errback)
            (my-send system text callback errback))
 :remote t
 :cancel (lambda (handle) (my-abort handle))
 :description "My model server")
#+end_src

The default cancel function kills a process or a buffer, so many backends do not need =:cancel=.

* Stage 1 replacements
#+INDEX: Stage 1
#+INDEX: contractions
#+INDEX: rule files

Stage 1 is self-contained and needs no other package.
It reads the bundled contraction table, then each file in =latex-parser-skill-replacement-files=, then =latex-parser-skill-replacement-alist=.
A later source overrides an earlier one for the same trigger.

A rule file is a CSV file of =trigger,replacement= lines.
Lines that start with =#= are comments, and a header line is skipped.
Triggers may hold several words.
Matching ignores case, respects word boundaries, skips LaTeX commands and comments, and keeps the case of the original.

Contractions that end in ='s= or ='d= have two readings, such as "it's" for "it is" or "it has".
By default Stage 1 leaves them for the model, which reads the whole sentence.
Set =latex-parser-skill-skip-ambiguous= to nil to expand them with the first reading.

Triggers listed in =latex-parser-skill-replacement-deny= never fire.
Set =latex-parser-skill-run-replacements= to nil to skip the stage.

An external program can replace the built-in engine.
The string =%f= in an argument becomes the name of a temporary file that holds the text, and the program prints the result.

#+begin_src emacs-lisp
(setq latex-parser-skill-replacement-command
      '("python3" "/path/to/apply_replacements.py" "%f" "--skip-ambiguous" "-o" "-"))
#+end_src

* Verification rules
#+INDEX: verification
#+INDEX: violations

Stage 3 mirrors the Verification section of the skill.
Errors trigger the repair pass, and warnings only appear in the report.

#+ATTR_LATEX: :booktabs t
#+CAPTION: Checks run by Stage 3.
| Check          | Level   | Rule                                                              |
|----------------+---------+-------------------------------------------------------------------|
| =preamble=     | Error   | No =\documentclass=, =\usepackage= or document environment lines  |
| =index=        | Error   | Every =\subsubsection= is followed by an =\index= line            |
| =contraction=  | Error   | No contraction from the table remains, and possessives are fine   |
| =sound=        | Error   | No sound description such as =(coughing)= remains                 |
| =todo=         | Error   | The TODO block is closed and comes last                           |
| =todo=         | Warning | No TODO block was found                                           |
| =dash=         | Error   | No em-dash or triple hyphen appears                               |
| =one-sentence= | Warning | A line may hold two sentences                                     |

Choose the checks with =latex-parser-skill-verify-checks= and extend the sound list with =latex-parser-skill-sound-descriptions=.
The repair pass runs for every backend.
=latex-parser-skill-repair-attempts= sets how many passes each chunk may get, and zero turns the stage off.

* Commands
#+INDEX: commands

#+ATTR_LATEX: :booktabs t
#+CAPTION: Interactive commands.
| Command                              | Purpose                                                 |
|--------------------------------------+---------------------------------------------------------|
| =latex-parser-skill-region=          | Parse the active region                                 |
| =latex-parser-skill-buffer=          | Parse the buffer, or only its document body             |
| =latex-parser-skill-dwim=            | Region when active, otherwise buffer                    |
| =latex-parser-skill-file=            | Parse a file and write =NAME_parsed.tex=                |
| =latex-parser-skill-verify-buffer=   | Run Stage 3 on the region or body and show a report     |
| =latex-parser-skill-replace-region=  | Run Stage 1 alone on the region                         |
| =latex-parser-skill-insert-preamble= | Insert the preamble lines that the output needs         |
| =latex-parser-skill-select-backend=  | Switch the backend for this session                     |
| =latex-parser-skill-cancel=          | Cancel the running job                                  |
| =latex-parser-skill-show-log=        | Show the log buffer                                     |
| =latex-parser-skill-menu=            | Open the transient menu                                 |

The region and buffer commands run only in LaTeX modes.
Set =latex-parser-skill-check-mode= to nil to lift that limit.
One job runs at a time.

** Where the result goes
#+INDEX: output actions
#+INDEX: preview buffer

=latex-parser-skill-output-action= decides what happens to the result of a region or buffer command.

#+ATTR_LATEX: :booktabs t
#+CAPTION: Output actions.
| Value          | Behavior                                                             |
|----------------+----------------------------------------------------------------------|
| =preview=      | Default. Shows the result for review before anything is replaced     |
| =replace=      | Replaces the source text in one undo step                            |
| =insert-after= | Inserts the result after the source text                             |
| =new-buffer=   | Opens the result in a new buffer                                     |
| =file=         | Writes =NAME_parsed.tex= beside the buffer's file                    |

The file command follows =latex-parser-skill-file-output-action=, whose default is =file=.
=latex-parser-skill-overwrite= decides what happens when the output file exists.

The package remembers the source text.
When the source changed during the request, it refuses to replace it and opens the result in a new buffer.

* Programmatic and batch use
#+INDEX: batch use
#+INDEX: audio workflow

Other code can call the pipeline directly.
This suits an audio-to-LaTeX workflow that already produces a transcript file.

#+begin_src emacs-lisp
(latex-parser-skill-process-string
 text
 (lambda (latex violations) (insert latex))
 :backend 'claude-code
 :errback (lambda (msg) (message "Failed: %s" msg)))
#+end_src

=latex-parser-skill-process-string-sync= waits for the result and returns a cons of the fragment and the violations.
=latex-parser-skill-finished-hook= runs after every delivery with the same two values.
From the shell, the batch entry point writes =NAME_parsed.tex= for each file.

#+begin_src sh
emacs --batch -L ~/6112MooersLabGitHubLabRepos/latex-parser-skill-el \
      -l latex-parser-skill -f latex-parser-skill-batch notes.txt
#+end_src

* Privacy
#+INDEX: privacy

With =latex-parser-skill-confirm-remote= on, the package asks once per session before a backend sends text off the computer.
A request larger than =latex-parser-skill-warn-size= characters asks first too.
Use a local model for unpublished data and for anything covered by a data use agreement.
The log buffer keeps requests and replies in memory only, and nothing is written to disk unless you save it.

* Updating the bundled prompt
#+INDEX: prompt file
#+INDEX: sync-prompt

=latex-parser-skill-prompt-file= points at =prompts/transcript-parser.md=.
It may point at an installed =SKILL.md= instead, and the front matter is removed before use.
=make sync-prompt= copies the body of the installed skill into the bundled file.
=make check-prompt= compares the two and fails when they differ.
Both targets read =~/.claude/skills/transcript-parser/SKILL.md= unless =SKILL= names another file, for example =make check-prompt SKILL=path/to/SKILL.md=.
